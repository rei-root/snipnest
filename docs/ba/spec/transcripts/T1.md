# Глоссарий

Термины проекта «Оркестратор автономной разработки». Определения даны в формулировках интервью от 2026-10-16.

| Термин | Определение |
|---|---|
| Оркестратор | Центральный агент системы. Координирует фазы разработки, арбитрит спорные ситуации (например, оспаривание тестов), пишет регламент арбитража при первой задаче. Не зависит от среды запуска. |
| BA (бизнес-аналитик) | Скилл/роль, проводит стартовое интервью с человеком о желаемом продукте. Фиксирует требования и критерии приёмки. Решает, являются ли задачи связными. |
| Тестописатель | Агент, пишет тесты трёх типов (unit, integration, e2e) последовательно. |
| Кодер | Агент, пишет код под тесты. Может оспорить тест у оркестратора. |
| Стартовое интервью | Диалог BA с человеком в начале работы. Цель — вытянуть всю информацию, чтобы человек больше не возвращался до фазы правок. |
| Фаза | Этап работы оркестратора. Базовый поток: спецификация → тесты → код → финальная проверка. |
| Спецификация (спека) | Документ, описывающий требования к продукту в форме, пригодной для написания тестов и кода. Источник истины для арбитража. |
| Тест | Артефакт, описывающий проверяемое поведение. Считается неизменчивым, кроме арбитража. |
| Unit-тест | Тест на отдельную функцию/модуль. |
| Интеграционный тест | Тест на несколько компонентов вместе. |
| E2E-тест | Тест на весь продукт. В MVP — без UI-автоматизации (API, CLI, логика); UI тестирует человек. |
| Арбитраж | Процедура решения спора кодера с оркестратором по поводу теста. Решение — по правилам (спека + регламент арбитража). |
| Регламент арбитража | Документ с правилами арбитража. Пишется оркестратором при первой задаче, применяется ко всем последующим. |
| Принятое решение | Запись в спеке обоснованного предположения оркестратора, принятого при нехватке данных. Содержит обоснование. |
| Traceability | Связь требование → тест. «Соответствие требованиям» проверяется по полноте этой связи. |
| Чек-лист критериев приёмки | Список пунктов «что продукт должен уметь», формируется BA на стартовом интервью. Проверяется в финале. |
| Связные задачи | Задачи в одной предметной области (один продукт/бизнес, разные стороны: клиент, сервер, админка). Несвязные задачи оркестратор не берёт. |
| Цикл правок | Запуск нового цикла разработки после «готово» по запросу человека. Откат к спеке целиком, обновление тестов и кода. |
| Журнал действий | Лог всех действий оркестратора. Хранится локально и в git. Используется для восстановления после сбоя. |
| Env-agnostic | Свойство оркестратора не зависеть от среды запуска (локально, удалённо, CLI, чат — без разницы). |
| Готово | Состояние задачи: продукт работоспособен ∧ все тесты зелёные ∧ соответствие требованиям по всем трём слоям проверки. |
