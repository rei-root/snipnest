# Snipnest

GUI-обёртка над [gallery-dl](https://github.com/mikf/gallery-dl) и
[yt-dlp](https://github.com/yt-dlp/yt-dlp): скачивание из Pinterest и видео
с YouTube без терминала.

Приложение вызывает уже установленные в системе бинарники и показывает ход
загрузки: прогресс, скорость, счётчик «скачано X из Y», список файлов и итог
(скачано / пропущено / ошибок).

## Возможности

- одно поле ссылки: приложение само определяет источник — Pinterest (картинка
  или альбом) или YouTube (видео, короткая ссылка, Shorts);
- несколько загрузок одновременно, каждая независимо;
- drag-and-drop ссылки из браузера в окно;
- выбор папки сохранения, выбор запоминается между запусками;
- лог вывода исполнителя для диагностики (сворачиваемая область);
- токен Pinterest хранится в системном хранилище (keyring), пароль не вводится;
- кнопка «Открыть Pinterest» — открывает сайт в браузере;
- кнопки «Путь к gallery-dl» и «Путь к yt-dlp» — если бинарник не найден в PATH;
- ярлык в меню приложений: **Snipnest**.

## Устройство

```
src/snipnest/
├── links.py       разбор ссылки Pinterest: картинка или альбом
├── youtube.py     разбор ссылки YouTube: видео, короткая ссылка, Shorts
├── binaries.py    поиск внешнего бинарника и окружение для его запуска
├── downloader.py  запуск gallery-dl, разбор его вывода, общие события загрузки
├── ytdlp.py       запуск yt-dlp, разбор его вывода, прогресс по потокам
├── jobs.py        состояния загрузки, права, видимость, прогресс
├── manager.py     список загрузок и параллельный запуск
├── settings.py    папка сохранения, пути к бинарникам, токен в хранилище
├── sources.py     слой источников: Pinterest и YouTube (расширяемо на TikTok)
└── ui/            интерфейс на PySide6
    ├── app.py          запуск приложения
    ├── window.py       главное окно
    ├── controls.py     поле ссылки, папка сохранения, кнопки
    ├── panel.py        список загрузок и файлы выбранной загрузки
    ├── presenter.py    правила показа события загрузки
    ├── controller.py   очередь, потоки, отмена и повтор
    ├── bridge.py       перенос событий из рабочего потока в GUI-поток
    ├── dnd.py          приём ссылки, перетащенной из браузера
    ├── logarea.py      сворачиваемая область лога
    ├── dialogs.py      диалоги (токен, выбор папки, путь к бинарнику)
    └── settings_actions.py  операции над настройками
```

Загрузка идёт в отдельном потоке; события попадают в GUI-поток через
сигналы Qt, поэтому окно не подвисает.

### Окружение запуска gallery-dl

Приложение запускает `gallery-dl` с очищенным окружением: из `PATH`
убирается каталог venv самого приложения, а `PYTHONHOME` и `PYTHONPATH`
сбрасываются.

Причина: многие установки `gallery-dl` — это bash-обёртки вида
`exec python3 .../gallery_dl/__main__.py`. Если первым в `PATH` стоит
`bin` venv приложения, то `python3` указывает на venv, где нет `requests`,
и бинарник падает с `ModuleNotFoundError` вместо скачивания. Системный
Python при этом остаётся доступен, поэтому `/usr/bin/gallery-dl` с
закреплённым shebang работает как раньше.

### Куда складываются файлы

Выбранная папка — конечная точка, а не база для дерева каталогов:

- картинка кладётся прямо в выбранную папку, без своих подкаталогов;
- альбом кладётся в одну папку с названием альбома (название берёт
  gallery-dl из данных Pinterest), файлы альбома лежат в ней;
- видео YouTube кладётся одним файлом прямо в выбранную папку.

Приложение задаёт это опцией `directory` gallery-dl: пустой шаблон — файл
прямо в выбранной папке, `{board[name]:?//}` — одна папка с названием доски.
Картинка отличается от альбома по числу файлов: приложение считает их
предварительным проходом (он же даёт счётчик «скачано X из Y»). Имена файлов
по-прежнему определяет gallery-dl.

### Видео с YouTube

Видео качает `yt-dlp` — у gallery-dl своего экстрактора YouTube нет.
Приложение узнаёт ссылку сама: обычное видео (`/watch?v=`), короткая ссылка
(`youtu.be`), Shorts (`/shorts/`), прямая трансляция (`/live/`) и вставка
(`/embed/`).

- качается лучшее доступное качество с предпочтением mp4 (H.264 и AAC);
  видео и звук приходят отдельными потоками и склеиваются в один файл
  средствами `ffmpeg`;
- файл называется «Название ролика [id].mp4» и лежит прямо в выбранной
  папке;
- одна ссылка — одно видео: плейлист целиком не скачивается;
- прогресс настоящий: yt-dlp отдаёт процент и скорость по каждому потоку,
  приложение считает общий процент по всем потокам сразу;
- уже скачанный файл не перекачивается — загрузка считается пропущенной;
- ошибка yt-dlp (ролик недоступен, возрастное ограничение, проверка бота)
  показывается в логе и переводит загрузку в состояние «ошибка».

YouTube решает JavaScript-задачи, поэтому для полного набора форматов
нужен JS-рантайм: `deno` (включён по умолчанию) или `node`
(подключается сам, если установлен). Если скриптов задачи нет, yt-dlp
предупреждает, что часть форматов может пропасть, — предупреждение видно
в логе. Полный набор скриптов ставится пакетом `yt-dlp-ejs`; скачивать их
из сети во время загрузки приложение не разрешает — это решение владельца.

### Расширение на другие источники

UI не знает про Pinterest и YouTube: он спрашивает реестр источников, какой
из них умеет работать со ссылкой. Чтобы добавить TikTok, достаточно
написать подкласс `DownloadSource` и зарегистрировать его:

```python
from snipnest.sources import DownloadSource, SourceKind, SourceRegistry

class TikTokSource(DownloadSource):
    kind = SourceKind.TIKTOK
    title = "TikTok"

    def matches(self, url: str) -> bool:
        return url.startswith("https://www.tiktok.com/")

registry = SourceRegistry()
registry.register(TikTokSource())
```

Правки в UI не нужны.

## Требования

- Python 3.11+
- `gallery-dl`, установленный в системе (для Pinterest)
- `yt-dlp`, установленный в системе (для YouTube)
- `ffmpeg` — им yt-dlp склеивает видео со звуком
- KDE / любой графический сеанс Linux

## Установка

```bash
uv sync
```

## Запуск

```bash
uv run snipnest
```

или

```bash
uv run python -m snipnest
```

Ярлык в меню приложений ставится так:

```bash
bash packaging/install-desktop-entry.sh
```

Скрипт делает три вещи:

- копирует `packaging/snipnest.desktop` в `~/.local/share/applications`
  (ярлык в меню приложений);
- ставит иконку `logo/snipnest.png` в
  `~/.local/share/icons/hicolor/*/apps/snipnest.png` во всех
  стандартных размерах и копирует `index.theme` темы hicolor — без него
  локальный каталог перекрывает системный, и иконка не находится;
- создаёт лаунчер `~/.local/bin/snipnest`, потому что ярлык
  вызывает команду по имени (`Exec=snipnest`), а интерпретатор
  приложения живёт в venv и в `PATH` меню не попадает.

После этого приложение доступно из меню приложений как
**Snipnest**.

Если каталог проекта переехал, лаунчер надо переустановить: он зашивает
путь к проекту.

## Разработка

```bash
make lint        # ruff check + format --check
make typecheck   # mypy --strict
make test        # unit-тесты, без сети
make test-live   # тесты с реальной загрузкой из Pinterest
make oracle      # оракул задачи: тесты + драйвер знаменателя
make ci          # всё вместе
```

Тесты интерфейса идут на платформе `offscreen`, если в системе нет
графической сессии (`DISPLAY` и `WAYLAND_DISPLAY` не заданы). Файл
`conftest.py` в корне задаёт это условие.
