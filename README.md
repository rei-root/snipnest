# Snipnest

GUI-обёртка над [gallery-dl](https://github.com/mikf/gallery-dl) и
[yt-dlp](https://github.com/yt-dlp/yt-dlp): скачивание из Pinterest и видео
с YouTube без терминала.

Приложение вызывает уже установленные в системе бинарники и показывает ход
загрузки: прогресс, скорость, счётчик «скачано X из Y», список файлов и итог
(скачано / пропущено / ошибок).

## Возможности

- одно поле ссылки: приложение само определяет источник — Pinterest (картинка
  или альбом) или YouTube (видео, короткая ссылка, Shorts);
- несколько загрузок одновременно, каждая независимо;
- drag-and-drop ссылки из браузера в окно;
- выбор папки сохранения, выбор запоминается между запусками;
- выбор формата сохранения: для картинки — JPEG, PNG, WebP или «как скачано»,
  для видео — контейнер (MP4, WebM, MKV), только звук или раздельные файлы;
- лог вывода исполнителя для диагностики (сворачиваемая область);
- токен Pinterest хранится в системном хранилище (keyring), пароль не вводится;
- строка меню: «Файл» (папка сохранения, настройки, токен, cookies, пути к
  бинарникам, компоненты, выход), «Вид» (тема окраски, лог) и «Справка»
  (о программе);
- окно настроек: папка сохранения, токен, cookies, пути к бинарникам и тема
  окраски в одном месте;
- тема окраски: тёмная, светлая или «как в системе» — переключается сразу,
  без перезапуска, и помнится между запусками;
- ярлык в меню приложений: **Snipnest**.

## Устройство

```
src/snipnest/
├── links.py       разбор ссылки Pinterest: картинка или альбом
├── youtube.py     разбор ссылки YouTube: видео, короткая ссылка, Shorts
├── binaries.py    поиск внешнего бинарника и окружение для его запуска
├── downloader.py  запуск gallery-dl, разбор его вывода, общие события загрузки
├── ytdlp.py       запуск yt-dlp, разбор его вывода, прогресс по потокам
├── jobs.py        состояния загрузки, права, видимость, прогресс
├── manager.py     список загрузок и параллельный запуск
├── formats.py     каталог форматов сохранения: картинки, видео, звук
├── branding.py    логотип, символ и иконки приложения (из одного SVG)
├── settings.py    папка сохранения, пути к бинарникам, токен в хранилище
├── sources.py     слой источников: Pinterest и YouTube (расширяемо на TikTok)
└── ui/            интерфейс на PySide6
    ├── app.py          запуск приложения
    ├── window.py       главное окно
    ├── controls.py     шапка окна, поле ссылки, папка сохранения
    ├── menus.py        строка меню: «Файл», «Вид», «Справка»
    ├── theme.py        тема окраски: тёмная, светлая, «как в системе»
    ├── settings_dialog.py  окно настроек
    ├── about.py        окно «О программе»
    ├── format_selector.py  выбор формата сохранения под вид ссылки
    ├── imaging.py      перевод картинки в другой формат (Qt)
    ├── panel.py        список загрузок и файлы выбранной загрузки
    ├── presenter.py    правила показа события загрузки
    ├── controller.py   очередь, потоки, отмена и повтор
    ├── bridge.py       перенос событий из рабочего потока в GUI-поток
    ├── dnd.py          приём ссылки, перетащенной из браузера
    ├── logarea.py      сворачиваемая область лога
    ├── dialogs.py      диалоги (токен, выбор папки, путь к бинарнику)
    └── settings_actions.py  операции над настройками
```

Загрузка идёт в отдельном потоке; события попадают в GUI-поток через
сигналы Qt, поэтому окно не подвисает.

### Окружение запуска gallery-dl

Приложение запускает `gallery-dl` с очищенным окружением: из `PATH`
убирается каталог venv самого приложения, а `PYTHONHOME` и `PYTHONPATH`
сбрасываются.

Причина: многие установки `gallery-dl` — это bash-обёртки вида
`exec python3 .../gallery_dl/__main__.py`. Если первым в `PATH` стоит
`bin` venv приложения, то `python3` указывает на venv, где нет `requests`,
и бинарник падает с `ModuleNotFoundError` вместо скачивания. Системный
Python при этом остаётся доступен, поэтому `/usr/bin/gallery-dl` с
закреплённым shebang работает как раньше.

### Куда складываются файлы

Выбранная папка — конечная точка, а не база для дерева каталогов:

- картинка кладётся прямо в выбранную папку, без своих подкаталогов;
- альбом кладётся в одну папку с названием альбома (название берёт
  gallery-dl из данных Pinterest), файлы альбома лежат в ней;
- видео YouTube кладётся одним файлом прямо в выбранную папку.

Приложение задаёт это опцией `directory` gallery-dl: пустой шаблон — файл
прямо в выбранной папке, `{board[name]:?//}` — одна папка с названием доски.
Картинка отличается от альбома по числу файлов: приложение считает их
предварительным проходом (он же даёт счётчик «скачано X из Y»). Имена файлов
по-прежнему определяет gallery-dl.

### Формат сохранения

Рядом с полем ссылки приложение предлагает выбрать, в каком виде останутся
файлы. Список зависит от ссылки: для картинки — форматы картинки, для видео —
форматы видео.

Для картинки (Pinterest):

- **Как скачано (без перекодировки)** — файл сохраняется в том формате, в
  каком его отдал сайт; это умолчание;
- **JPEG**, **PNG**, **WebP** — картинка перекодируется, и в папке остаётся
  один файл в выбранном формате: исходный заменяется;
- перекодируются только неподвижные картинки: анимированный GIF остаётся
  GIF, а видео с Pinterest не трогается;
- перекодировку делает само приложение (Qt), сторонние программы не нужны;
- уже скачанный файл не перекодируется: его и не качали.

Для видео (YouTube):

- **MP4** — видео со звуком (H.264 + AAC), умолчание;
- **WebM** — видео со звуком (VP9 + Opus);
- **MKV** — видео со звуком в контейнере, который берёт любые кодеки;
- **Только звук** — из ролика остаётся один аудиофайл (MP3, M4A, Opus, FLAC
  или WAV — выбирается рядом), видео в папке нет;
- **Видео и звук отдельными файлами** — в папке два файла: «Название [id]
  (видео).ext» без звука и «Название [id] (звук).ext» без видео; склейки нет.

Перекодировки видео не делается: выбирается контейнер, а не кодек. Извлечение
звука и склейка требуют `ffmpeg` — приложение передаёт его `yt-dlp` сам.

Последний выбор помнится между запусками: отдельно для картинок и для видео.

### Видео с YouTube

Видео качает `yt-dlp` — у gallery-dl своего экстрактора YouTube нет.
Приложение узнаёт ссылку сама: обычное видео (`/watch?v=`), короткая ссылка
(`youtu.be`), Shorts (`/shorts/`), прямая трансляция (`/live/`) и вставка
(`/embed/`).

- качается лучшее доступное качество с предпочтением mp4 (H.264 и AAC);
  видео и звук приходят отдельными потоками и склеиваются в один файл
  средствами `ffmpeg`;
- файл называется «Название ролика [id].mp4» и лежит прямо в выбранной
  папке;
- одна ссылка — одно видео: плейлист целиком не скачивается;
- прогресс настоящий: yt-dlp отдаёт процент и скорость по каждому потоку,
  приложение считает общий процент по всем потокам сразу;
- уже скачанный файл не перекачивается — загрузка считается пропущенной;
- ошибка yt-dlp (ролик недоступен, возрастное ограничение, проверка бота)
  показывается в логе и переводит загрузку в состояние «ошибка».

YouTube решает JavaScript-задачи, поэтому для полного набора форматов
нужен JS-рантайм: `deno` (включён по умолчанию) или `node`
(подключается сам, если установлен). Если скриптов задачи нет, yt-dlp
предупреждает, что часть форматов может пропасть, — предупреждение видно
в логе. Скрипты задачи ставятся пакетом `yt-dlp-ejs` (версия должна
совпадать с версией yt-dlp):

```bash
pip install --user "yt-dlp-ejs"
```

Скачивать эти скрипты из сети во время загрузки приложение не разрешает —
это решение владельца.

### Cookies для YouTube

YouTube перестал отдавать ролики анонимно: без входа он отвечает
«Sign in to confirm you're not a bot» и видео не скачивается. Cookies
берутся из браузера владельца или из файла — кнопка **«Cookies YouTube»**
в тулбаре.

В диалоге показывается, что найдено в системе: профили Firefox (каждый —
отдельным пунктом, потому что вход может быть не в каждом) и браузеры на
Chromium. Выбрать можно и файл `cookies.txt` в формате Mozilla/Netscape —
его владелец выгружает сам (yt-dlp умеет выгружать, но вместе с cookies
всех сайтов, поэтому приложение этого не делает).

Приложение cookies не читает и не сохраняет: в настройках лежит только
имя браузера с профилем либо путь к файлу. Логин и пароль не запрашиваются.

> [!CAUTION]
> Аккаунт, которым пользуются через yt-dlp, YouTube может заблокировать —
> временно или навсегда. Если это личный аккаунт, лучше завести отдельный
> для загрузок и качать им не часто.

### Расширение на другие источники

UI не знает про Pinterest и YouTube: он спрашивает реестр источников, какой
из них умеет работать со ссылкой. Чтобы добавить TikTok, достаточно
написать подкласс `DownloadSource` и зарегистрировать его:

```python
from snipnest.sources import DownloadSource, SourceKind, SourceRegistry

class TikTokSource(DownloadSource):
    kind = SourceKind.TIKTOK
    title = "TikTok"

    def matches(self, url: str) -> bool:
        return url.startswith("https://www.tiktok.com/")

registry = SourceRegistry()
registry.register(TikTokSource())
```

Правки в UI не нужны.

## Требования

- KDE / любой графический сеанс Linux
- для готовых артефактов — больше ничего: Python, Qt и внешние программы
  лежат внутри;
- для запуска из исходников: Python 3.11+, `gallery-dl` и `yt-dlp`
  в системе (либо поставленные мастером установки).

## Установка

Готовые сборки лежат в Releases репозитория.

**Установщик** — один файл: графическая программа, которая определяет
дистрибутив, показывает план установки и ставит приложение:

```bash
chmod +x snipnest-installer-linux-amd64.bin
./snipnest-installer-linux-amd64.bin
```

Файл из Releases хранится без исполняемого бита — поэтому сначала `chmod +x`.

В окне установщика видно, что он определил (система, версия glibc), что
будет поставлено и куда. Дальше — два варианта:

- **для всех пользователей**: образ в `/opt/snipnest`, лаунчер в
  `/usr/local/bin`, ярлык в меню приложений, иконки в `/usr/share/icons`.
  Пароль администратора спрашивает система (polkit);
- **только для себя**: те же файлы, но в `~/.local` — без прав
  администратора.

Зависимости (gallery-dl, yt-dlp, ffmpeg) установщик ставит родным
пакетным менеджером системы: `apt-get` на debian-based, `dnf` на
rhel-based, `pacman` на arch-based, `zypper` на suse-based, `apk` на Alpine,
`emerge` на Gentoo. Что ставить, решает человек: у каждой зависимости своя
галочка, по умолчанию отмечены все.

Самого приложения внутри установщика нет: он его скачивает из релиза и
проверяет по `SHA256SUMS`.

**Пакет .deb** (если хочется поставить пакетом вручную):

```bash
sudo apt install ./snipnest_0.2.3_amd64.deb
```

Если apt напечатал «Отказано в доступе» от служебного пользователя `_apt` —
пакет при этом ставится: apt просто не смог прочитать файл своим служебным
пользователем (домашний каталог закрыт для других) и отработал без песочницы.
Поставить пакет можно и совсем без apt:

```bash
sudo dpkg -i snipnest_0.2.3_amd64.deb
```

Пакет самодостаточный: внутри программа, Qt, переносимый Python и все пять
компонентов. После установки приложение работает без сети. Пакет большой
(около 230 МБ) — именно потому, что всё внутри.

**AppImage** — приложение целиком, без установки:

```bash
chmod +x snipnest-0.2.3-linux-glibc-2.38-x86_64.AppImage
./snipnest-0.2.3-linux-glibc-2.38-x86_64.AppImage
```

Имя образа говорит, под что он собран: платформа (`linux`), версия glibc
(`glibc-2.38`) и архитектура (`x86_64`). Образ работает на любой машине с
Linux; на системах без FUSE запускается через `--appimage-extract-and-run`.

## Компоненты

Приложение работает через внешние программы: `gallery-dl` (Pinterest),
`yt-dlp` (YouTube), `ffmpeg` (склейка видео со звуком), `deno` и
`yt-dlp-ejs` (скрипты задачи YouTube, без них часть форматов пропадает).

Мастер установки компонентов показывается при первом запуске, а потом —
кнопкой **«Компоненты…»** в тулбаре. В списке одна главная галочка
«Обеспечить все компоненты» и пять пунктов под ней; раскрытие списка
показывает каждый компонент отдельно, и отметку можно снять с любого.
Снятая галочка означает «не ставить»: без согласия ничего не скачивается.

Установленное лежит в `~/.local/share/snipnest/components` и находится
приложением само. Уже установленная в системе программа не скачивается
повторно. Скачанные архивы остаются в `~/.cache/snipnest/downloads`:
переустановка компонента не качает его заново.

## Запуск

```bash
uv run snipnest
```

или

```bash
uv run python -m snipnest
```

Версию можно посмотреть так:

```bash
uv run snipnest --version
```

Ярлык в меню приложений ставится так:

```bash
bash packaging/install-desktop-entry.sh
```

Скрипт делает три вещи:

- копирует `packaging/snipnest.desktop` в `~/.local/share/applications`
  (ярлык в меню приложений);
- ставит иконку `logo/snipnest.svg` в
  `~/.local/share/icons/hicolor/*/apps/snipnest.png` во всех
  стандартных размерах и копирует `index.theme` темы hicolor — без него
  локальный каталог перекрывает системный, и иконка не находится;
  рядом кладётся векторная иконка `hicolor/scalable/apps/snipnest.svg`.
  PNG-размеры режутся из того же SVG средствами Qt — внешняя программа
  (ImageMagick) не нужна;
- создаёт лаунчер `~/.local/bin/snipnest`, потому что ярлык
  вызывает команду по имени (`Exec=snipnest`), а интерпретатор приложения
  живёт в venv и в `PATH` меню не попадает.

Если нет живого venv (`$ROOT/.venv/bin/python`), иконка не обновляется —
прежняя остаётся на месте, — но установка не прерывается.

После этого приложение доступно из меню приложений как
**Snipnest**.

Если каталог проекта переехал, лаунчер надо переустановить: он зашивает
путь к проекту. Там же нужен живой venv — после переезда его консольные
скрипты остаются со старыми путями, и лечится это `uv sync --reinstall`.

## Разработка

```bash
make lint        # ruff check + format --check
make typecheck   # mypy --strict
make test        # unit-тесты, без сети
make test-live   # тесты с реальной загрузкой из Pinterest
make oracle      # оракул задачи: тесты + драйвер знаменателя
make ci          # всё вместе
```

Сборка артефактов (нужна сеть: скачиваются переносимый Python, ffmpeg и
deno):

```bash
make dist-installer  # dist/snipnest-installer-linux-amd64.bin — установщик
make dist-appimage   # dist/snipnest-<версия>-linux-glibc-<версия>-x86_64.AppImage
make dist-deb        # dist/snipnest_<версия>_amd64.deb
make dist            # все три
make check-dist      # проверить собранные артефакты
```

Собирается только под `amd64`. Артефакты собираются в CI по тегу версии
(`vX.Y.Z`) и выкладываются в Releases.

Тесты интерфейса идут на платформе `offscreen`, если в системе нет
графической сессии (`DISPLAY` и `WAYLAND_DISPLAY` не заданы). Файл
`conftest.py` в корне задаёт это условие.
